아키텍처 접근법 — 어떤 방식으로 만들까요?

GM이 각 역할 에이전트의 tmux 세션에 태스크를 전달하는 방법

A

tmux send-keys 직접 주입 (추천)

GM이 계획을 세운 후, tmux send-keys로 각 역할 세션에 태스크를 직접 입력. 사용자는 세션에 attach해서 에이전트와 직접 대화 가능.

장점

  • claude-squad와 동일한 패턴
  • 에이전트가 진짜 claude 세션 (컨텍스트 유지)
  • 사용자 개입이 자연스러움

단점

  • tmux 출력 파싱이 복잡
  • 완료 감지가 어려움
B

파일 기반 핸드오프

GM이 각 worktree에 TASK.md를 작성. 각 역할 세션의 claude가 이 파일을 읽어서 처리. 결과는 OUTPUT.md로 저장.

장점

  • 완료 감지가 명확
  • 각 단계 결과물이 파일로 남음

단점

  • 에이전트가 파일 감시해야 함
  • 실시간성이 떨어짐
C

하이브리드 (tmux + 파일)

GM이 파일로 태스크 기록 + tmux send-keys로 에이전트를 트리거. 출력은 파일로 캡처. 두 방식의 장점만.

장점

  • 감사 로그 + 실시간성 동시
  • 에이전트 재시작 시 복구 가능

단점

  • 구현 복잡도 높음
  • 상태 동기화 필요
