# 최소 코드 사다리 (Minimal-Code Ladder)

코드를 쓰기 전에 **안 써도 되는 길**부터 따진다. 게으름은 부주의가 아니라 효율이다 —
가장 좋은 코드는 끝내 쓰지 않은 코드다. 구현 스킬·서브에이전트가 과설계로 흐르지 않게
하는 횡단 규칙.

> [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) (MIT) 차용 —
> "The best code is the code never written." 벤치마크상 베이스라인 대비 코드량 80~94%↓.
> 프로젝트 CLAUDE.md "Simplicity First / Surgical Changes"의 파이프라인 실행 버전이다.

## 사다리 (먼저 걸리는 칸에서 멈춘다)

1. **애초에 존재할 필요가 있나?** 추측성 요구는 만들지 말고 한 줄로 그 사실을 말한다. (YAGNI)
2. **표준 라이브러리가 하나?** 쓴다.
3. **플랫폼 네이티브 기능이 덮나?** `<input type="date">` > 피커 라이브러리, CSS > JS, DB 제약 > 앱 코드.
4. **이미 설치된 의존성이 푸나?** 쓴다. 몇 줄이면 될 일에 새 의존성 추가 금지.
5. **한 줄로 되나?** 한 줄로.
6. **그때서야:** 동작하는 최소 코드.

사다리는 연구 과제가 아니라 반사다. 두 칸이 다 되면 위 칸을 잡고 넘어간다.
**처음 되는 게으른 해법이 정답이다.**

## 규칙

- **요청 안 한 추상화 금지**: 구현체 하나뿐인 인터페이스, 산출물 하나뿐인 팩토리, 절대 안 바뀌는 값의 config 금지.
- **"나중을 위한" 보일러플레이트·스캐폴딩 금지.** 나중은 나중에 알아서 만든다.
- **추가보다 삭제. 영리함보다 지루함.** 영리한 코드는 새벽 3시에 누군가 해독한다.
- **파일 수 최소, 가장 짧은 동작 diff가 이긴다.**
- 표준 라이브러리 두 선택지가 같은 크기면 **엣지케이스에 옳은 쪽**을 잡는다. 게으름은 코드를 덜 쓰는 것이지 더 허술한 알고리즘을 고르는 게 아니다.
- 복잡한 요청? 게으른 버전을 내고 같은 응답에서 의심한다: "X 했고 Y가 덮는다. 전체 X 필요하면 말해달라." 기본값으로 갈 수 있는 답에서 멈추지 않는다.

## `ponytail:` 주석 — 의도된 단순화 표시

의도적으로 단순화한 지점은 `ponytail:` 주석으로 표시한다. 단순함이 무지가 아니라 의도임을 남긴다.
알려진 천장이 있는 지름길(전역 락, O(n²) 스캔, 단순 휴리스틱)은 **천장과 업그레이드 경로**를 함께 적는다:

```
# ponytail: 전역 락. 처리량이 문제되면 계정별 락으로.
```

## 게으르면 안 되는 것

다음은 **절대 단순화로 깎아내지 않는다** (사다리보다 우선):

- 신뢰 경계의 입력 검증, 데이터 손실을 막는 에러 처리 — [PII 마스킹](pii-masking.md)·[사람 게이트](human-gate.md)와 함께 지킨다.
- 보안 조치, 접근성 기본, **명시적으로 요청된 것**.
- 비자명 로직(분기·루프·파서·돈/보안 경로)은 **깨지면 실패하는 가장 작은 검증 하나**를 남긴다 — assert 기반 self-check 또는 작은 `test_*` 하나. 프레임워크·픽스처 불필요. 자명한 한 줄짜리는 테스트 면제(테스트에도 YAGNI).
- 사용자가 전체 버전을 고집하면 만든다. 재론쟁 없음.

## 출력 형식

**코드 먼저.** 그다음 최대 세 줄: 무엇을 건너뛰었나, 언제 추가하나.
설명이 코드보다 길면 설명을 지운다 — 단순화를 변호하는 문단은 산문으로 밀반입한 복잡성이다.
단, 사용자가 명시적으로 요청한 설명(리포트·워크스루·단계별 노트)은 빚이 아니므로 온전히 준다.

```
[코드] → 건너뜀: [X], 추가 시점: [Y].
```
