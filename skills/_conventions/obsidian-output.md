# 보고서 옵시디언 정리 (Obsidian Output)

**규칙: 사용자가 읽는 보고서형 산출물(완료 보고·QA 판정·회고·조사 결과·보안 감사·릴리즈 보고)은 옵시디언 볼트 `40_프로젝트/{프로젝트}/보고서/`에 정리본으로 저장한다. 프로젝트 폴더는 기존 폴더를 먼저 매칭하고, 없을 때만 새로 만든다.**

## 왜

볼트는 하네스의 장기 기억이다([obsidian-context.md](obsidian-context.md)) — 그런데
읽기만 하고 쓰지 않으면 기억이 자라지 않는다. `.state/` 산출물은 휘발이고 archive는
백업일 뿐, 사람이 나중에 찾아 읽고 위키링크로 연결하는 곳은 볼트다. 보고서가 볼트에
쌓이면 프로젝트별 이해가 축적된다 — 팀(미래의 나 포함)이 같은 정신 모형을 다시 로드할 수 있다.

## 커널 (인라인 허용)

```bash
_VAULT="${OBSIDIAN_VAULT_DIR:-$HOME/obsidian-vaults/AI 에이전트}"
[ -d "$_VAULT" ] || echo "미수행: 옵시디언 볼트 없음"
ls "$_VAULT/40_프로젝트/" 2>/dev/null   # 기존 프로젝트 폴더 목록 — 매칭 판단의 입력
# 매칭 규칙으로 {프로젝트 폴더}를 정한 뒤:
mkdir -p "$_VAULT/40_프로젝트/{프로젝트 폴더}/보고서"
```

## 프로젝트 폴더 매칭 규칙

1. `40_프로젝트/`의 **기존 폴더 목록을 먼저 본다.** 현재 프로젝트와 같은 프로젝트를 가리키는 폴더가 있으면 그 폴더를 쓴다. 판단 근거:
   - 저장소 디렉토리명(`basename "$PWD"`)과의 일치 (대소문자 무시)
   - `docs/sj-company/PROJECT.md`의 프로젝트명·goal
   - **영문↔한글 표기 차이도 같은 프로젝트로 취급** (예: `upflow` 저장소 ↔ `업플로우` 폴더, `totaro_web` ↔ `totaro`)
2. 명확한 매칭이 없으면 `40_프로젝트/{저장소 디렉토리명}/`을 **새로 만들어** 넣는다.
3. **애매하게 비슷한 폴더에 끼워 넣지 않는다** — 확신이 없으면 새 폴더가 낫다. 잘못 합쳐진 기억은 나중에 가를 수 없지만, 쪼개진 폴더는 사람이 합칠 수 있다.

## 저장 형식

1. 파일명: `{YYYY-MM-DD} {보고 종류}.md` (예: `2026-07-15 QA 판정.md`). 같은 날 같은 종류가 이미 있으면 ` -2` 붙임 — 기존 파일 덮어쓰기 금지.
2. frontmatter: `date` / `run`(RUN_ID, 없으면 생략) / `skill` / `kind`(완료 보고·QA 판정·회고·조사·보안 감사·릴리즈).
3. 본문: **그 자체로 읽히는 정리본** — 서술식 보고([literate-report.md](literate-report.md)) 또는 판정·핵심 발견 요약. 로그·diff 원문 덤프 금지. 원본(`.state/` 경로 등)은 마지막 줄에 경로로 연결.
4. 저장 전 [PII 마스킹](pii-masking.md): `password|token|secret|api.?key|Bearer|private.?key` 패턴 값을 `[REDACTED]` 치환 — 볼트는 영속 파일이다.

## 비차단

볼트가 없으면 **그대로 진행**하고 사용자 보고에 `미수행: 옵시디언 볼트 없음` 한 줄을
남긴다([honest-report.md](honest-report.md)). 볼트 저장 실패가 파이프라인을 막지 않는다.

`.state/` 휘발 파일·컨텍스트 파일 자체(보고서가 아니라 파이프라인 내부 산출물).

## obsidian-writer와의 관계

이 컨벤션은 **보고서 산출 자동 정리에 한정**된다. 그 외 볼트 쓰기(지식 문서·프로젝트
문서 작성)는 여전히 obsidian-writer 스킬의 몫이다.
