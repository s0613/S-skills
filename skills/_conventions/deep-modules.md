# 깊은 모듈 (Deep Modules)

**작은 인터페이스 뒤에 많은 동작을 둔다.** 에이전트는 코딩을 빠르게 만드는 만큼 코드베이스의 엔트로피도
빠르게 올린다 — 얇은 래퍼·패스스루·"테스트하려고 뽑은" 함수가 쌓여 개념 하나를 이해하려면 파일 열 개를
오가야 한다. 이 규칙은 설계·리뷰·구조 점검에서 같은 어휘로 말하게 한다.

> [mattpocock/skills](https://github.com/mattpocock/skills) `codebase-design` (Matt Pocock, MIT) 차용 —
> John Ousterhout *A Philosophy of Software Design*, Michael Feathers의 seam 개념.

## 어휘 (이 단어를 그대로 쓴다)

| 용어 | 뜻 | 피할 말 |
|------|-----|---------|
| **모듈** | 인터페이스와 구현이 있는 모든 것. 함수·클래스·패키지·계층을 가로지르는 조각 — 크기 무관 | 컴포넌트, 서비스, 유닛 |
| **인터페이스** | 호출자가 올바르게 쓰려면 알아야 하는 *전부* — 타입 시그니처 + 불변식·호출 순서·에러 모드·필수 설정·성능 특성 | API, 시그니처 (너무 좁다) |
| **깊이** | 인터페이스의 레버리지. 배워야 할 인터페이스 대비 쓸 수 있는 동작의 양. 깊다 = 작은 인터페이스 뒤에 많은 동작, 얕다 = 인터페이스가 구현만큼 복잡 | — |
| **이음매(seam)** | 그 자리를 고치지 않고도 동작을 바꿀 수 있는 곳 — 인터페이스가 놓이는 *위치* | 경계(boundary) |
| **어댑터** | 이음매에서 인터페이스를 채우는 구체물. 내용이 아니라 *역할*을 가리킨다 | — |
| **레버리지** | 호출자가 깊이에서 얻는 것 — 구현 하나가 N개 호출 지점과 M개 테스트에 돌려준다 | — |
| **국소성** | 유지보수자가 깊이에서 얻는 것 — 변경·버그·지식·검증이 한곳에 모인다. 한 번 고치면 다 고쳐진다 | — |

## 원칙

- **삭제 테스트.** 모듈을 지운다고 상상한다. 복잡성이 사라지면 패스스루였다. 복잡성이 N개 호출자에게 다시
  퍼지면 제 몫을 하던 모듈이다.
- **인터페이스가 곧 테스트 표면이다.** 호출자와 테스트는 같은 이음매를 건넌다. 인터페이스를 *지나쳐서*
  테스트하고 싶다면 모듈 모양이 틀렸다.
- **어댑터 하나면 가짜 이음매, 둘이면 진짜.** 실제로 갈아끼울 것(보통 운영 + 테스트)이 없으면 포트를 만들지 않는다.
  이건 [minimal-code](minimal-code.md)의 "구현체 하나뿐인 인터페이스 금지"와 같은 말이다.
- **깊이는 추상화를 늘리는 게 아니다.** 대개 얕은 래퍼를 *지우고 합쳐서* 얻는다. 깊은 모듈도 내부는 작은 부품으로
  나뉠 수 있다 — 그 부품을 인터페이스에 드러내지 않을 뿐이다.
- **의존성은 받고, 결과는 돌려준다.** 안에서 `new StripeGateway()` 하지 말고 인자로 받는다.
  `cart.total -= x` 하지 말고 할인을 반환한다.

## 의존성 종류 → 테스트 방법

| 종류 | 예 | 깊게 만들 때 |
|------|-----|-------------|
| 프로세스 안 | 순수 계산, 메모리 상태 | 합치고 새 인터페이스로 바로 테스트. 어댑터 불필요 |
| 로컬 대체 가능 | PGLite(Postgres), 메모리 파일시스템 | 대체물을 테스트에서 띄운다. 이음매는 내부, 외부 포트 없음 |
| 원격이지만 우리 것 | 사내 마이크로서비스·내부 API | 이음매에 포트 정의 → 운영은 HTTP 어댑터, 테스트는 메모리 어댑터 |
| 진짜 외부 | Stripe·Twilio | 포트로 주입, 테스트는 목 어댑터 |

## 테스트: 겹치지 말고 바꾼다

깊어진 모듈의 인터페이스에 테스트가 생기면 **얕은 모듈들에 붙어 있던 옛 단위 테스트는 지운다.**
테스트는 인터페이스로 관찰 가능한 결과만 단언한다. 구현을 바꿀 때 같이 바뀌어야 하는 테스트는 인터페이스를
지나쳐서 테스트하고 있는 것이다.
