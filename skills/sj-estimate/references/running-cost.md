# 운영 실비 산정 — AWS · AI

> 견적에 "AI 비용", "서버 비용"을 **추측으로 쓰지 않는다.** 이 파일의 단가표와 계산법으로
> 실제 사용량을 곱해 낸다. 단가가 바뀌면 이 파일만 고친다.

## 1. AI 비용 — 계산 전에 "AI가 필요한가"부터 판정한다

**이 순서를 건너뛰면 견적이 틀린다.** 고객이 "AI 적용"을 요청했다고 모든 기능에 AI를 넣으면
비용이 오르고 정확도가 떨어진다. 기능마다 먼저 판정한다.

| 답의 모양 | 무엇을 쓰나 |
|----------|------------|
| 규칙·계산·정확한 조회 (근무시간 집계, 연차 일수, 금액 합계, 날짜 계산) | **그냥 코드.** LLM을 끼우면 검산할 수 없는 값이 나온다 |
| 좁은 판단 (분류·라우팅·참거짓·후보 선택) | 판단 모델 또는 소형 LLM 1회 호출 |
| 자유 형식 자연어 → 구조화 / 문장·코드 생성 / 다단계 추론 | **LLM** |

경험칙: 사내 업무 시스템 기능 10개 중 AI가 실제로 들어가는 자리는 **1~3개**다.
견적서에는 그 판정표를 그대로 싣는다 — "왜 AI 비용이 이렇게 싼가"에 대한 답이자,
경쟁사의 뭉뚱그린 "AI 적용비 수천만원"과 갈리는 지점이다.

### 고객이 "AI"라고 부르는 세 가지를 분리한다

| 고객 표현 | 실체 | 견적상 위치 |
|-----------|------|------------|
| Claude Code / AI 코딩 | 제품 기능이 아니라 **개발 방식** | 별도 항목 아님 — **M/M 자체를 낮추는 요인**으로 설명 |
| AI Agent | 운영 중 실제로 도는 LLM 호출 | 해당 기능 안에 포함 + 월 실비로 별도 표기 |
| MCP | 에이전트를 도구에 잇는 규약. 운영 시스템의 기능이 아니다 | 1차 구축 제외, 운영 옵션 |

### 모델 단가 (Claude API, 2026-06 공식 가격표 기준)

| 모델 | 입력 $/1M tok | 출력 $/1M tok | 쓰는 자리 |
|------|--------------|--------------|----------|
| Claude Haiku 4.5 | $1.00 | $5.00 | 구조화 추출, 분류, 정규화 — **업무 시스템 기본값** |
| Claude Sonnet 5 | $2.00 | $10.00 | 요약, 리포트 생성, 가벼운 추론 |
| Claude Opus 5 | $5.00 | $25.00 | 복잡한 추론. 업무 시스템에는 과하다 |

할인: **Batch API 50%** (지연 허용 일괄 처리), **프롬프트 캐시 읽기 약 0.1배**
(캐시는 최소 프리픽스 길이가 있어 짧은 프롬프트엔 안 걸린다 — 안 걸리는 쪽으로 보수적으로 잡는다).

### 계산 절차

```
월 비용 = Σ (월 건수 × 입력토큰/건 ÷ 1,000,000 × 입력단가)
        + Σ (월 건수 × 출력토큰/건 ÷ 1,000,000 × 출력단가)
그리고 × 2  ← 재시도·오분류 재요청·테스트 여유
```

토큰 추정: 한국어는 대략 **1자 ≈ 1.3토큰**. 시스템 프롬프트 + 참조 목록(거래처·계정과목)이
입력의 대부분을 차지한다. 출력은 JSON이면 보통 200~400토큰.

**같은 입력에 대한 여러 질문은 한 호출에 묶는다** — 따로 부르면 입력 토큰을 두 번 낸다.

### 자주 쓰는 사례 (2026-09 기준 실계산)

| 용도 | 모델 | 월 건수 | 입력/건 | 출력/건 | 월 비용 |
|------|------|---------|---------|---------|---------|
| Slack·메일 자유형식 → 구조화 | Haiku 4.5 | 600 | 1,800 | 330 | $2.07 |
| 상품·거래처명 → 카테고리 분류 | Haiku 4.5 (Batch) | 100 | 400 | 60 | $0.04 |
| 주간 리포트 요약 | Sonnet 5 | 24 | 8,000 | 800 | $0.58 |

**소규모 사내 시스템의 AI 실비는 보통 월 1만원 이하다.** 이 사실을 숨기지 않는다 —
정직하게 밝히는 쪽이 신뢰를 얻고, 운영비의 근거가 인프라가 아니라 **개발 인력**임을 분명히 한다.

비싸지는 경우는 하나다 — **이미지를 매번 모델에 올리는 설계**(영수증·도면 판독).
재시도마다 이미지가 다시 올라가 곱해진다. 견적에 넣기 전에 리사이즈·캐시·재시도 상한을 먼저 설계한다.

## 2. AWS 비용 — 서울 리전(ap-northeast-2) 온디맨드

환율은 **1,400원/USD**로 계산하고 견적서에 환율을 명시한다.

### 어느 구성으로 쓸 것인가 — 먼저 정한다

| 다루는 데이터 | 구성 | 월 실비 |
|---------------|------|---------|
| 사내 공지·자산 대장·단순 신청 등 **잃어도 다시 만들 수 있는 것** | 최소 구성 | 약 119,000원 |
| **인사·급여·계약서·자금 이체** 등 잃으면 복구가 불가능하거나 법적 문제가 되는 것 | 정상 구성 | **약 342,000원** |

**정상 구성이 비싼 이유는 세 가지이고, 이 셋은 깎지 않는다** — ① DB 자동 백업 + 5분 단위
시점 복구 ② 서버를 사설 서브넷에 두고 로드밸런서로만 노출(+NAT 게이트웨이) ③ 배포 전
검증용 스테이징 분리. 최소 구성으로 급여 데이터를 올리면 싸지만, 사고가 나면 끝난다.

> **실비를 견적서에 공개하면 그 숫자는 약속이 된다.** 342,000원을 써 놓고 단일 EC2로
> 돌리면 거짓말이다. 쓴 대로 세울 것이 아니면 쓰지 않는다.

  퍼블릭 서브넷 + 보안그룹으로 바꾸면 6.9만원이 빠지지만, 그러면 DB가 있는 망이 직접 노출된다.
- **개발 기간 중**: 개발 + 스테이징 + 운영 환경 사전 구축 3개월 ≈ **약 78만원**. 구축비에 포함한다.
- **확장 시** (매장 10개 초과 · 보관 3년 초과): 월 **+8만~15만원**. 확인 항목 표에 이 행을 넣는다.

### 운영비를 정하기 전에 반드시 계산할 것

```
운영 월 마진 = 운영비 − 실비 − (월 보장 시간 × 시간당 내부 원가) − 운영 관리비
```

**이 계산을 건너뛰면 운영이 적자인 채로 팔린다.** 실비가 34만원인데 월 100만원에
16시간을 보장하면(16 × 31,250 = 50만) 마진이 사라진다. 실비를 크게 잡는 것은
고객 설득에는 좋지만 **우리 손익을 그만큼 깎는다** — 둘을 같은 화면에서 본다.

세 가지 조절 손잡이: ① 보장 시간을 줄인다 ② 구성을 줄인다(그러면 견적서 실비표도 고친다)
③ 운영을 본전으로 두고 2차 프로젝트에서 번다. **고르고, 고른 이유를 내부 검토란에 적는다.**

### 견적에 반드시 같이 넣는 세 가지

비용 급증의 1순위 용의자는 EC2 시간이 아니라 **데이터 전송(out)**이다.
리버스 프록시를 우회해 앱 포트로 직접 나가면 압축이 빠져 전송량이 5~10배가 된다.

1. 압축(gzip/zstd) 경유 강제 — 앱 포트 직접 노출 금지
2. 목록 API 페이지네이션 + ETag — 변화 없음 확인에 전량을 받지 않는다
3. **CloudWatch 알람 `NetworkOut` 1시간 합계 > 평소 3배** + **AWS Budgets 월 한도 50/80/100% 알림**

3번은 선택이 아니다. 비용 경보 없는 계정에 과금 자원을 올리지 않는다.

### 자원이 없어도 청구되는 것 (제외 범위에 명시)

Savings Plans · 예약 인스턴스 · Route53 호스팅존(존당 $0.50) · RDS 확장 지원 · EIP(개당 월 약 $3.6)
