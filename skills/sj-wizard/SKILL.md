# sj-wizard — 사람이 해야 하는 단계를 실행 가능한 스크립트로

> 차용: [mattpocock/skills](https://github.com/mattpocock/skills) `wizard` (MIT). 라이브러리 원문은
> [vendor/template.sh](vendor/template.sh), 커밋은 `vendor/UPSTREAM_COMMIT`, 라이선스 `vendor/LICENSE`.

채팅에 "1. 콘솔 열기 2. … 6. 복사"를 적으면 스크롤로 사라지고, 다음에 또 설명해야 한다. 위저드는
그 절차를 **실행되는 프로그램**으로 만든다. 사람은 클릭하고 붙여 넣고 Enter만 누른다.

`template.sh`가 UX를 이미 다 갖고 있다 — 단계별 진행 표시, 확인 관문, OS별 URL 열기, 숨김 입력,
`.env` 멱등 갱신(0600), `gh secret`/`gh variable`, 마지막 요약. **할 일은 절차의 범위를 잡고 단계를 쓰는 것뿐이다.**
`STAGES` 표시 위의 라이브러리는 모든 위저드에서 같다 — 절대 손대지 않는다.

## Step 1 — 범위 잡기

사람이 해야 할 단계와 그 과정에서 받는 값을 전부 찾는다. **묻기 전에 repo를 읽는다:**

- 셋업: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, 프레임워크 설정,
  `.github/workflows/*`(모든 `secrets.*`·`vars.*` 참조가 위저드가 만들어야 할 값이다).
- 전환·마이그레이션: 현재 상태, 목표 상태, 그 사이의 되돌릴 수 없는 동작.
- **AWS가 끼면** 첫 단계는 `aws sts get-caller-identity`로 계정 확인, 과금 자원을 만드는 단계 앞에는
  예산 경보 확인 단계를 둔다(전역 AWS 비용 규칙).

그다음 단계 목록과 단계별로 나오는 값을 보여 주고 확인받는다 — 추가·삭제·순서 변경 가능.

**완료:** 모든 단계가 순서대로 이름 붙었고, 받는 값마다 (a) 사람이 어디서 얻는지 (b) 어디에 쓰는지
(`.env` / GitHub secret / GitHub variable / 다른 도구 설정(명령으로 등록, 예: `claude mcp add`) / 여러 곳 / 안 씀) (c) 비밀인지(숨김 입력) 공개인지 안다.

## Step 2 — 단계별 경로 확정

단계마다 사람이 따라갈 정확한 경로를 쓴다: 열 URL, 그 화면에서 할 일, 값이 보이는 위치, 채울 변수.
예: "대시보드 → Developers → API keys → Reveal test key → 복사".
현재 UI·명령을 **실제로 모르면 그렇다고 말하고** 사용자에게 묻거나 공식 문서를 확인한다 —
있지도 않은 메뉴를 지어내지 않는다.

**완료:** 모든 단계가 처음 보는 사람도 따라 할 수 있는 구체적 지시로 이어진다.

## Step 3 — 위저드 작성

1. `vendor/template.sh`를 대상 경로로 복사한다. 기본은 스크래치 디렉토리(1회용), 다음 사람도 쓸
   셋업 경로면 사용자 확인 후 `scripts/wizard-{slug}.sh`.
2. 예시 단계(Stripe)를 지우고, 의존 순서대로 단계당 `stage` 하나씩 쓴다. 헬퍼만 쓴다:
   `stage`, `say`/`step`/`note`/`warn`, `open_url`, `ask`/`ask_secret`, `write_env`,
   `set_secret`/`set_var`, `pause`/`confirm`. 헬퍼에 없는 명령(다른 도구에 값 등록 등)은 `confirm` 뒤에
   직접 실행하고, 도구가 없거나 실패하면 `SKIPPED+=("무엇을 손으로 할지")`로 남겨 마지막 요약에 나오게 한다.
   `banner` 제목과 단계 문구는 **한국어**로 쓴다.
3. `TOTAL_STAGES`를 실제 단계 수로 맞춘다.

지킬 기준: 값을 묻기 전에 그 값이 있는 URL을 먼저 연다(같은 페이지를 이어 쓰는 다음 단계는 다시 열지 않고 `say`로 이어 간다) · 비밀은 무조건 `ask_secret` · 남길 값은 전부
`write_env` · `set_secret`은 CI가 실제로 쓰는 값만 · 되돌릴 수 없는 동작 앞엔 `confirm` ·
단계 하나는 화면 하나(단계마다 화면이 지워지므로 넘치면 필요한 줄이 사라진다).

## Step 4 — 정적 검증 후 인계

- `bash -n <script>`, 있으면 `shellcheck <script>`. `chmod +x`.
- **끝까지 실행하지 않는다** — 브라우저를 열고 사람 입력을 기다린다. 대신 정적으로 추적한다:
  Step 1의 모든 값이 받아지고 Step 1이 정한 곳에 써지는지, 모든 `set_secret` 이름이 CI의
  `secrets.*` 참조와 정확히 일치하는지.
- 사용자에게 실행 방법을 한 줄로 준다. `.env`는 **실행한 디렉토리**에 써지므로 대상 프로젝트로 이동을 포함한다:
  `! cd <대상 프로젝트> && bash <스크립트 경로>`. `.env`를 안 쓰는 위저드면 이동은 생략.
  저장소에 남길 셋업 경로면 README에서 링크한다.

**완료:** 검증 출력과 추적 결과(값 → 목적지 표)를 보고했다.

## 계약

- **비밀값을 대화로 받지 않는다.** 키는 사람이 스크립트에 숨김 입력으로 넣는다 — 범위 잡기 중에도
  "키를 붙여 주세요"라고 하지 않는다. 사용자가 채팅에 붙여 넣으면 이미 컨텍스트에 들어갔음을 알리고 교체를 권한다.
- **권한 부여·`sudo`·결제·키 발급은 사람 게이트** — 위저드가 그 단계를 *안내*할 뿐, 에이전트가 대신하지 않는다
  ([human-gate](../_conventions/human-gate.md), [external-tools](../_conventions/external-tools.md)).
- **값이 평문으로 남는 곳을 알린다** — CLI 인자·다른 도구 설정 파일에 들어가는 비밀은 그 단계 `note`와 인계 보고에
  "어디에 평문으로 저장되는지"를 적는다. 도구가 환경 변수·표준 입력을 받으면 인자 대신 그쪽을 쓴다.
- **비대화형 실행** — Step 1의 확인을 받을 사람이 없으면 단계 목록을 가정으로 정하고 인계 보고의 `## 가정`에
  적는다. 스크립트 자체는 써도 되지만 실행은 여전히 사람 몫이다 ([noninteractive](../_conventions/noninteractive.md)).
- 생성한 스크립트를 실행했다고 말하지 않는다. 첫 실행은 사람의 몫이고, 그 실행이 테스트다
  ([honest-report](../_conventions/honest-report.md)).
- `vendor/template.sh`를 고칠 일이 생기면 업스트림 커밋을 확인해 통째로 교체하고 `UPSTREAM_COMMIT`을 갱신한다.
