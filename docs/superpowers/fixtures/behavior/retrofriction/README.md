# 픽스처 — 케이스 E (sj-retro)

friction 로그에 **신스키마 2건 + 구스키마 2건**이 섞여 있다. 구스키마 항목에는
`severity`가 없고 `where`/`note`를 쓴다 — 초기 기록의 실제 형태다.

2026-08-28에 이 조합이 sj-retro의 문서화된 조회 레시피를 `KeyError: 'severity'`로
죽였다. 로그가 비어 있는 것보다 이게 나빴다 — 채워도 읽히지 않았기 때문이다.

이 케이스는 그 수정을 고정한다. 읽는 쪽이 구스키마를 흡수해야 하며,
로그는 append-only라 과거를 고쳐 쓰는 것으로 통과시킬 수 없다.
