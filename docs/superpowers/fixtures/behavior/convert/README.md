# 픽스처 — 케이스 J·K (sj-convert)

`inbox/`에 **Read 툴이 읽는 파일**(`notes.txt`)과 **못 읽는 파일**(`spec.docx`)이 하나씩 있다.
이 스킬의 존재 이유는 그 경계이므로, 픽스처도 경계만 본다.

- **케이스 J**는 라우팅만 본다 — `문서 정리`라는 문자열이 #21(docs-organize)을 먼저 때리는데,
  파일 포맷이 명시되면 #28로 가야 한다.
- **케이스 K**는 스킬 Step 0이 실제로 되돌려 보내는지 본다. 전부 변환하는 구현은
  케이스 J를 통과하고 K에서만 걸린다.

`spec.docx`는 `textutil -convert docx`로 만든 실제 OOXML 파일이다 — 더미 바이트가 아니다.
